# Development Workflows

## Build

Normal debug build:

```powershell
bun ./cmd/build.ts
```

This builds the `SumatraPDF-dll` Visual Studio target in Debug x64 and writes `out/dbg64/SumatraPDF-dll.exe`.

The build script discovers MSBuild through `cmd/util.ts`. It currently prefers Visual Studio 18/2026 through `detectVisualStudio2026()` in `cmd/build.ts`, while other scripts may use `detectVisualStudio()` to fall back to VS 2022.

If `bun` is not in PATH, use the direct MSBuild fallback documented in `build-instructions.md`.

## Format

After changing C/C++ files under `src`, run clang-format on the touched files before building. Do not format vendored code under `mupdf` or `ext`.

For whole-tree formatting, `cmd/format.ts` finds clang-format through Visual Studio and formats the project-owned C++ paths it knows about:

```powershell
bun ./cmd/format.ts
```

For small patches, formatting only the touched files is usually safer.

## Tests

Issue tests live in `tests`. Each test exports `testit()` and can also be run standalone through `runStandalone()` from `tests/util.ts`.

Run one issue test:

```powershell
bun tests/issue-5633.ts
```

Run one issue test without rebuilding:

```powershell
bun tests/issue-5633.ts --no-build
```

Run all registered issue tests:

```powershell
bun tests/all.ts
```

Native utility tests are built through:

```powershell
bun ./cmd/run-tests.ts
```

When adding a new issue test, follow the repository convention:

- Add `tests/issue-<number>.ts`.
- Export `export async function testit(): Promise<void>`.
- End with the standalone `if (import.meta.main) { await runStandalone(testit); }` runner.
- Use shared helpers from `tests/util.ts`, especially `EXE`, `buildApp`, and `runStandalone`.
- Register the test in `tests/all.ts`.

## Generated Files

Several user-visible tables are generated from TypeScript definitions:

- Settings: edit `cmd/gen-settings.ts`, then run `bun cmd/gen-settings.ts` to regenerate `src/Settings.h` and `src/Settings.cpp`.
- Commands: edit `cmd/gen-commands.ts`, append before `CmdNone`, run `bun cmd/gen-commands.ts`, and update `docs/md/Commands.md` and `docs/md/Version-history.md`.
- Flags: edit `cmd/gen-flags.ts`, run `bun cmd/gen-flags.ts`, implement handling in `Flags.cpp`, and update `docs/md/Version-history.md`.

Visual Studio project files are generated by Premake. If source files are added or removed, update the Premake file list and run:

```powershell
bun ./cmd/premake.ts
```

## Manual App Testing

Always test the DLL target:

```powershell
./out/dbg64/SumatraPDF-dll.exe -for-testing <file>
```

`-for-testing` starts a new instance, avoids session restore, and avoids writing normal settings.

For debugging:

```powershell
windbgx -Q -o -g ./out/dbg64/SumatraPDF-dll.exe
```
